# Lessons

Registro compacto de aprendizajes activos que deben mejorar el comportamiento del kit.

Este archivo no es un diario histórico ni inbox de señales. Mantenerlo corto. Las señales crudas van primero a `docs/kit-improvement/inbox.md`. Si una lección se repite o cambia una regla de trabajo, promoverla al archivo correcto: `AGENTS.md`, un agente específico, un skill específico, `ROUTING.md`, `TESTING_POLICY.md` u otro artefacto operativo.

## Política

- Registrar sólo aprendizajes que eviten errores futuros relevantes.
- No registrar señales crudas sin triage; usar `docs/kit-improvement/inbox.md`.
- No registrar preferencias menores, decisiones puntuales ya resueltas o detalles que pertenecen al backlog.
- Cada lección debe tener dueño, alcance y estado.
- Revisar periódicamente las lecciones activas y promover o archivar.

## Estados

- `candidato`: observado una vez; revisar antes de convertir en regla.
- `activo`: regla temporal que debe considerarse en tareas similares.
- `promovido`: ya fue incorporado al comportamiento base en un agente, skill o documento operativo.
- `archivado`: conservado sólo por trazabilidad histórica.

Alcance: tarea / feature / hito / proyecto / kit

Corrección o evidencia:

Regla nueva:

Promover a:

Fecha de revisión:
